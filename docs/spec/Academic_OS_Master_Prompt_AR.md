## Owner clarifications (2026-10-20) — binding constraints for design and build

1. **The owner has no computer** (phone/tablet only). Everything — running the server, deploying, building store apps, installing test
   builds — must be doable from a phone/tablet browser and cloud services: a cloud host with a persistent disk deployed from GitHub,
   store builds produced by cloud CI (e.g. macOS runners for iOS), test installs through TestFlight / Google Play internal testing.
   No step may require the owner to run a terminal on a local machine.
2. **Goal: stronger than the leading handwriting-notes apps, published on the App Store and Google Play, very smooth and very fast.**
   Writing latency and smoothness with a stylus are first-class requirements, not polish: the design must state honestly what a
   web canvas can reach and plan a native, low-latency ink surface (with stroke prediction) inside a native shell that reuses the
   existing web app and the same stroke data model and sync — not a rewrite of the whole product.
3. Until the store apps exist, the owner uses the hosted web app (PWA installed from the browser).
4. **Primary writing device: iPad + Apple Pencil.** The first native ink surface targets iPadOS (Swift; PencilKit or a custom
   Metal renderer, with Apple Pencil prediction, pressure/tilt/hover, double-tap/squeeze where the hardware has them), delivered
   through TestFlight then the App Store; Android follows on the same data model.
5. **Hosting choice delegated to the engineer ("the best place for the data, e.g. Cloudflare or another").** Decision (2026-10-20):
   the current server needs a long-running process with a persistent disk (node:sqlite, poppler/LibreOffice, background jobs),
   which Cloudflare Workers/Containers do not provide as-is, so the server runs on a phone-manageable host with a persistent disk
   (Render, deployed from GitHub with a blueprint), and **Cloudflare R2** (S3-compatible, no egress fees) holds off-site backups now
   and is the preferred object store for files in the multi-user design.

## 1. Advanced Notes & Document Engine

بناء محرر PDF وملاحظات احترافي يدعم:

- الكتابة بالقلم مع Pressure Sensitivity وPalm Rejection.
- أقلام متعددة، Highlighter، Pencil، Eraser، Shapes، Ruler وLasso.
- Vector Ink، وتحريك العناصر وتغيير حجمها وألوانها وشفافيتها.
- الكتابة باليد وتحويلها إلى نص.
- دعم العربية والإنجليزية واتجاهات RTL/LTR المختلطة.
- صور، جداول، رسوم، روابط، معادلات، تسجيلات صوتية وملاحظات جانبية.
- Undo/Redo، سجل تعديلات، Bookmarks، Tabs وSplit View.
- فتح محاضرتين معاً بتمرير مستقل أو متزامن.
- صفحات PDF وخلفيات كتابة مختلفة، مع Infinite Canvas اختياري.
- تصدير نسخة PDF مسطحة أو نسخة قابلة للتحرير.
- بحث داخل النصوص المطبوعة والكتابة اليدوية باستخدام OCR.
- عمل كامل دون إنترنت للملفات المحفوظة محلياً.

يجب المحافظة على سرعة الكتابة وسلاستها، وعدم إعادة رسم المستند بالكامل عند كل حركة قلم.

## 2. Academic Channels & University System

إنشاء منظومة أكاديمية مرتبة وفق التسلسل:

University → College → Department → Stage → Academic Year → Semester/Course → Subject → Lecture.

تحتوي كل مادة على:

- محاضرات رسمية مرتبة بالأرقام والتواريخ.
- ملفات PDF وPPTX وDOCX والصور.
- تحويل ملفات Office إلى PDF مع الحفاظ قدر الإمكان على التخطيط والخطوط.
- ملفات إضافية وملخصات وأسئلة السنوات السابقة.
- تسجيلات المحاضرات.
- مناقشات وأسئلة الطلاب.
- شروحات الطلاب المنشورة.
- آخر التحديثات وإصدارات المحاضرات.
- واجهة لإظهار التقدم في الدراسة.

يدخل الطالب للقناة بواسطة Class Code أو QR Code أو رابط دعوة، ويمكن للمشرف تحديد الصلاحيات والموافقة على الانضمام.

إضافة Subscribe to Course للاشتراك بمادة كاملة، وإضافة محاضراتها الجديدة تلقائياً إلى مكتبة الطالب.

زر Start Studying ينشئ نسخة شخصية قابلة للتعديل من المحاضرة، مع إمكانية اختيار شرح طالب آخر قبل البدء.

## 4. Smart Fork, Followed Copy & Collaborative Documents

هذه من أهم ميزات المنصة.

كل محاضرة رسمية تكون مصدراً أساسياً واحداً، ويمكن إنشاء نسخ متعددة منها دون تكرار البيانات الأصلية بلا حاجة.

دعم ثلاثة أنماط:

Independent Fork: نسخة مستقلة تحتوي على شرح الطالب الذي اختاره المستخدم، ويستطيع تعديلها دون الاعتماد على التحديثات المستقبلية.

Followed Copy: نسخة شخصية مرتبطة بشرح ناشر آخر، وتصل إليها تحديثات ذلك الشرح مع الحفاظ على ملاحظات المستخدم الخاصة.

Collaborative Copy: مستند مشترك يكتب عليه الطلاب المصرح لهم في الوقت نفسه.

تنفيذ نظام Layers يفصل بين:

- المحتوى الرسمي.
- شرح كل طالب.
- الملاحظات الشخصية.
- تعليقات المجموعة.
- التعديلات المقترحة.

إضافة إمكانيات متقدمة:

- إظهار وإخفاء أي Layer.
- نسخ Layer وحده أو دمج عدة Layers.
- أخذ رسومات من شرح طالب وملاحظات من طالب آخر.
- مقارنة نسختين جنباً إلى جنب.
- تحديث الشروحات مع خيار معاينة التغييرات.
- Version History وTime Machine لاستعادة الإصدارات.
- Stable Anchors لتثبيت الملاحظات على العناصر والصفحات الصحيحة.
- Attribution لحفظ نسبة الشرح إلى صاحبه.
- اقتراح تصحيحات على شرح منشور دون تعديل عمل صاحبه مباشرة.

ممنوع فقدان الملاحظات الشخصية عند تحديث المحاضرة أو شرح الطالب الآخر.

- ردود متسلسلة.

- إضافة السؤال إلى بنك الأسئلة.
- إنشاء Flashcard من الإجابة.

- البحث في أسئلة جميع طلاب المادة.

## 7. AI Live Lecture Recording — ميزة أساسية جداً

بناء نظام تسجيل ذكي للمحاضرات يعمل بالتزامن مع الكتابة وعرض PDF.

### Mixed Arabic-English Speech Recognition

يجب فهم كلام الدكتور المختلط بين:

- اللهجة العراقية.
- العربية الفصحى.
- الإنجليزية.
- المصطلحات الطبية والعلمية.
- الجمل التي تحتوي عدة لغات في الوقت نفسه.

مثال:

«اليوم راح نشرح Anatomy of the Abdomen، وبعدين نشوف anterior relations of the stomach، وهذا الموضوع مهم جداً للامتحان».

يجب تحويل الكلام إلى نص صحيح قدر الإمكان، مع الحفاظ على المصطلحات الإنجليزية الأصلية وعدم ترجمتها أو تشويهها.

القدرات المطلوبة:

- Streaming ASR.
- Code-Switching Detection.
- Medical Terminology Recognition.
- Custom Vocabulary لكل مادة.
- Speaker Diarization عند الإمكان.
- Noise Reduction.
- Voice Activity Detection.
- Silence Detection.
- إزالة فترات الصمت أثناء التشغيل اختيارياً، مع الاحتفاظ بالتسجيل الأصلي.
- تقسيم التسجيل إلى Topics وChapters.
- Playback Speed والتحكم بالقفز بين الأجزاء.
- تصحيح التفريغ النصي يدوياً دون إتلاف الربط الزمني.

### Audio–PDF–Ink Synchronization

اربط في Timeline واحد:

1. كلام الدكتور.
2. التفريغ النصي.
3. الصفحة المفتوحة.
4. حركة القلم والرسومات والتظليل.
5. الصور التي التقطها الطالب.
6. الأسئلة والملاحظات التي كتبها.
7. العلامات المهمة التي اكتشفها AI.

عند الضغط على جملة بالتفريغ، ينتقل التطبيق إلى وقت التسجيل والصفحة المناسبة.

وعند الضغط على كتابة الطالب، يمكن إعادة تشغيل الصوت الذي كان يسمعه أثناء كتابتها.

## 8. AI Exam Radar & Automatic Question–Answer Detection

أريد نظاماً يكتشف إشارات أهمية الأسئلة في كلام الدكتور.

مثل:

- «هذا سؤال امتحاني».
- «ركزوا على هذا الموضوع».
- «هذا مهم جداً».
- «دائماً يجي بالامتحان».
- «ممكن أسألكم عن...».
- «What is the most common cause of...».

عند اكتشاف هذه العبارات:

- إنشاء Exam Highlight.
- حفظ التوقيت والصفحة.
- تحديد السؤال الفعلي إذا ذكره الدكتور.
- التقاط إجابة الدكتور إن وجدت.
- التمييز بين إجابة الدكتور والإجابة التي يولدها الذكاء الاصطناعي.
- توليد إجابة إضافية مع شرح ومصدر عندما تكون المعلومات كافية.
- تحويل السؤال إلى MCQ أو Flashcard.
- إضافة السؤال تلقائياً إلى قائمة مراجعة مقترحة.
- إنشاء Exam Radar Dashboard بعد المحاضرة.

تدعم الميزة كشف الأهمية من التكرار والسياق والكلام الصريح، لكن لا يجوز تقديم توقعات الامتحان باعتبارها مؤكدة.

إذا كانت الإجابة غير واضحة أو لم يذكرها الدكتور، يجب توضيح ذلك بدلاً من اختلاقها.

## 9. Unified Live AI Copilot

أريد تشغيل عدة وظائف مع التسجيل في الوقت نفسه:

- Live Transcription.
- Live Translation.
- Live Summarization.
- Live Question Detection.
- Live Answer Assistance.
- Live Topic Recognition.
- Live Slide Synchronization.
- Live Flashcard Suggestions.

تظهر في واجهة جانبية هادئة لا تشتت الطالب.

مثلاً عند قول الدكتور:

«هذا سؤال مهم: What are the branches of the celiac trunk؟»

يكتشف النظام السؤال، ويربطه بالمحاضرة والوقت، ويعرض الإجابة إن توفر مصدر موثوق، ويمكن إضافتها إلى ملاحظاتي بضغطة واحدة.

يجب ألا يعطل AI التسجيل أو الكتابة بالقلم. تكون معالجة الصوت والتفريغ والشرح مستقلة عن واجهة الرسم.

دعم Offline Recording دائماً، مع إمكانية تشغيل نماذج محلية على الأجهزة المناسبة. إذا لم تتوفر قدرة AI محلياً، يُحفظ المحتوى وتُستكمل المعالجة عند توفر اتصال، دون الادعاء أن كل الميزات تعمل بلا إنترنت.

## 11. Offline-First & Nearby Classroom Sync

أريد نظام تعاون ومشاركة قوي يعمل عند انقطاع الإنترنت داخل القاعات الدراسية.

### Nearby Device Discovery

تكتشف الأجهزة القريبة بعضها بعضاً وتسمح بتكوين غرفة محلية بواسطة:

- Nearby Connections عندما يناسب الأجهزة المستهدفة.
- Bluetooth LE للاكتشاف والتواصل المناسب له.
- Wi-Fi / Local Network لنقل الملفات والتحديثات بكفاءة.
- Native Networking APIs أو بدائل مدعومة حسب Android وiOS.
- QR Pairing وSession Codes.

يجب اختبار التوافق الحقيقي بين Android وiPhone وiPad، وعدم افتراض توفر جميع وسائل الاتصال على جميع الأجهزة.

### Offline Collaboration

بعد انضمام الطلاب وموافقتهم، يمكنهم:

- استقبال المحاضرة الأصلية.
- متابعة تعديلات صاحب الشرح.
- رؤية الكتابة والتظليل المشترك.
- تبادل الملفات والصور.
- إرسال الأسئلة داخل الغرفة.
- استقبال Updates وAnnotation Deltas بدلاً من إعادة إرسال PDF كاملاً.
- مواصلة الدراسة عند انقطاع الاتصال.
- استكمال النقل والمزامنة عند عودة الاتصال.
- المزامنة مع السيرفر لاحقاً.

استخدم CRDT/Operation Log أو نموذجاً متوافقاً لحل تعارضات الكتابة التعاونية، مع Version Vectors وContent Hashing وإعادة المحاولة والنقل المجزأ.

أضف تشفير الاتصالات، قبول الدعوات، صلاحيات واضحة، والتحقق من سلامة الملفات. لا تُرسل ملفات الطلاب الخاصة تلقائياً إلى أجهزة أخرى.

ادرس Store-and-Forward أو Peer Relay اختياري لتوسيع وصول التحديثات داخل القاعة، بشرط الموافقة وعدم تسريب المحتوى.

- تحليل الإجابات.

- إنشاء خطة تقوية بعد الامتحان.

## 13. Lecture Replay & Learning Timeline

بناء ميزة تتجاوز تسجيل الشاشة التقليدي.

احفظ أحداث الكتابة والتظليل والتنقل بين الصفحات مرتبطة بالزمن، مع التسجيل الصوتي.

عند تشغيل Replay يستطيع الطالب:

- مشاهدة إعادة كتابة الملاحظات بالتسلسل.
- سماع شرح الناشر المتزامن معها.
- القفز إلى موضوع معين.
- تغيير السرعة.
- إخفاء الصوت أو الكتابة.
- عرض النص المتزامن.
- نسخ لقطة أو رسمة إلى ملفاته.
- الانتقال مباشرة إلى سؤال امتحاني مهم.

إضافة Study Time Machine للعودة إلى حالة المحاضرة عند لحظة معينة أثناء شرحها.

## 14. AI Tutor & Intelligent Learning

إنشاء مدرس AI خاص بكل طالب، يرتبط بمحاضراته وملفاته وملاحظاته.

يستطيع:

- الإجابة عن الأسئلة المتعلقة بالمادة.
- تبسيط المفاهيم المعقدة.
- الشرح بالعربية مع المصطلحات الإنجليزية.
- إنشاء أمثلة وحالات تطبيقية.
- توليد MCQs بأساليب متعددة، بما فيها USMLE للمواد الطبية عند ملاءمتها.
- إنشاء Flashcards.
- تحليل الإجابات الخاطئة.
- تحديد نقاط الضعف.
- بناء خطط مراجعة.
- تطبيق Spaced Repetition وActive Recall.
- إنشاء ملخصات من محتويات ملفات متعددة.
- مراجعة المحاضرة نقطة بنقطة.
- توضيح العلاقات بين المحاضرات.

Source-First AI: يجب تفضيل محتوى المصدر المرتبط بالسؤال وإظهار المرجع والصفحة أو توقيت التسجيل، وفصل كلام الدكتور عن الشرح المولد وعن المعلومة المستمدة من مرجع خارجي.

لا يخترع الذكاء الاصطناعي مصادر أو اقتباسات. وعند وجود تعارض أو ضعف في الأدلة يوضحه.

## 22. Essential User Journeys & Acceptance Tests

لا تعتبر الميزة مكتملة إلا بعد اختبار سيناريوهات حقيقية مثل:

### Scenario 1 — المحاضرة المباشرة

يفتح الطالب PDF، يبدأ التسجيل، يكتب بالقلم، يتحدث الدكتور بمزيج عربي وإنجليزي، ويذكر سؤالاً مهماً. يحفظ النظام الصوت والكتابة والتوقيت، ويكشف السؤال، ويعرض إجابة موثقة إن توفرت.

### Scenario 2 — نسخ شرح طالب

يدخل طالب إلى المحاضرة الخامسة، يختار شرح زميل، ينشئ Followed Copy، ثم يكتب ملاحظاته الخاصة. عندما يحدث الزميل شرحه، تظهر التحديثات دون ضياع أي كتابة شخصية.

### Scenario 3 — بدون إنترنت

يدخل طلاب القاعة في جلسة محلية، يشاركون محاضرة وتعديلات على طبقة مشتركة، ثم ينقطع الاتصال بين جهازين. تُحفظ التغييرات محلياً وتُستأنف المزامنة دون تكرار أو فقدان عند الاتصال مجدداً.

### Scenario 4 — تحديث المحاضرة الرسمية

يرفع المشرف إصداراً جديداً من المحاضرة يتضمن إدراج صفحات. يحافظ النظام على ملاحظات الطالب، وينقل ما يمكن مطابقته بأمان، ويعرض ما يحتاج مراجعة يدوية.

### Scenario 5 — مراجعة الامتحان

يختار الطالب مادة وموعد الامتحان، فيجمع النظام المحاضرات والأسئلة الموثقة وعلامات الدكتور وبطاقات المراجعة ويقترح خطة دراسية قابلة للتعديل.

### Scenario 6 — البحث بالصورة

يرفع الطالب صورة سلايد، فيحدد النظام المحاضرة المحتملة، ويعرض الصفحات المطابقة مع درجة الثقة، دون اختلاق نتيجة إذا تعذرت المطابقة.

اختبر أيضاً:

- الأداء على الأجهزة الضعيفة.
- استهلاك البطارية أثناء التسجيل والكتابة.
- التزامن بين 3 أجهزة أو أكثر.
- Android ↔ iPad عند دعم وسيلة الاتصال.
- تضارب التعديلات.
- انقطاع النقل في منتصف الملف.
- إعادة تشغيل التطبيق أثناء المزامنة.
- سلامة البيانات بعد استعادة نسخة احتياطية.
- الصلاحيات والتسريبات المحتملة.
- جودة ASR على عينات صوتية عربية–إنجليزية واقعية.
- دقة ربط الصوت بالصفحات والكتابة.

### Implementation Priority

Phase 1: محرر المحاضرات، القنوات، التحويل، الكتابة، المكتبة الشخصية، النسخ والطبقات.

Phase 2: الشروحات العامة، الحسابات الاجتماعية، التحديثات، التعليقات، المقارنة والبحث.

Phase 3: تسجيل المحاضرات، التفريغ المختلط، مزامنة الصوت والكتابة، Exam Radar.

Phase 4: المشاركة القريبة دون إنترنت، الغرف، التعاون، وحل التعارضات.

Phase 5: AI Tutor، التعلم التكيفي، Knowledge Graph، الشروحات الجماعية والابتكارات المتقدمة.

هذه المراحل تحدد ترتيب التنفيذ، وليست مبرراً لإهمال تصميم الترابط بين الأنظمة منذ البداية.

### Final Non-Negotiable Rules

- لا تحذف أو تختصر أي ميزة مطلوبة دون توثيقها.
- لا تنفذ كل شيء في مكون واحد ضخم.
- لا تبنِ مجرد Mockups أو أزرار شكلية.
- لا تدّعِ اكتمال ميزة دون اختبارها.
- لا تسمح لفشل AI بتعطيل الكتابة أو التسجيل.
- لا تفقد بيانات الطلاب عند انقطاع الإنترنت.
- لا تستبدل الملاحظات الشخصية عند تحديث محتوى مشترك.

- أعطِ الأولوية لتكامل الميزات، سرعة التطبيق، سهولة الاستخدام، ودقة المحتوى.
