# Requirement Matrix (§59, §61)

One row per section of the spec ([`docs/spec/MedLevo_AI_Master_Prompt_AR.txt`](spec/MedLevo_AI_Master_Prompt_AR.txt),
§00–§62), then one row per acceptance scenario (§60, AC-01 … AC-30). Written 2026-10-10 in the integration and
acceptance round.

**What the statuses rest on.** Every status comes from evidence that can be checked in this repository: the code (routes,
tables, capability registrations), the test files named in the row, the module notes
([`docs/modules/*.md`](modules/)), [`docs/ACCEPTANCE.md`](ACCEPTANCE.md) (adversarial acceptance groups G1–G8 and the
critic sweep), [`docs/CAPABILITY_MATRIX.md`](CAPABILITY_MATRIX.md) and [`docs/PERFORMANCE.md`](PERFORMANCE.md). The live
capability states quoted below were read from `GET /api/capabilities` on a fresh server with no AI key. The run of the
suites that backs the «Tested» claims is in [`docs/TEST_LOG.md`](TEST_LOG.md).

## Legend

| status | meaning |
|---|---|
| **Implemented & Tested** | the code exists and at least one automated test that was run exercises it (test files named in the row). Server-side AI guarantees count as tested only through the test-only scripted / fake provider, and the row says so |
| **Implemented (not tested on device)** | built, but not verified by an automated test or on its real target device (§61: «لا تخلط Implemented مع Tested»). For the two document-only rows (§00, §59) it means: the document exists, and nothing machine-checks it |
| **Partial** | part of the section works and is tested; the rest is named in the notes as *Not Started* or *Blocked* |
| **Not Started** | nothing usable exists |
| **Blocked (X)** | the code exists but cannot do its job here because X is missing. AI rows: implemented, server guarantees tested with the test-only scripted provider, never run with a real model; the real server reports `requires_configuration` with the reason |

A row whose main part works but which has a sub-part that cannot run here carries **Blocked part:** in its notes.

No AI key exists in this environment. Every AI path (explain, chat, Study Book, summaries, compare, figure explanation,
generated questions, answer check, written grading, case generation, AI viva judge) was exercised only with the
test-only `FakeAiProvider` / `ScriptedAi` in server tests. In real-server E2E runs these features answer
`AI_NOT_CONFIGURED` / `requires_configuration`, and the E2E specs assert exactly that.

Test paths use these prefixes: `srv:` = `apps/server/test/`, `web:` = `apps/web/`, `sh:` = `packages/shared/test/`,
`e2e:` = `e2e/`. A bare name such as `g2-ac07` right after a full path is the sibling file in the same folder
